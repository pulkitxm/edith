# Host rebuild measurement procedure

The JSON and Markdown size reports describe the exact local artifacts measured at their recorded time. Regenerate them only after the final integrated host and all 39 indexed worker packages have been built and independently verified. `all-indexed-packages-measured` establishes artifact coverage. It does not establish merge readiness, production signing, successful lifecycle or native UI tests, or release publication. Until those final artifacts and checks exist, retain the earlier report's recorded scope and date rather than presenting it as complete.

Final generation requires an explicit expected source commit, a matching clean checkout, and matching clean host build metadata. The generator validates ZIP length, SHA-256, expanded package bytes, CRC, the exact 39 package IDs, and their current source fingerprints. It rejects missing, extra, duplicate, changed, or stale artifacts. Use the runner's canonical package directory and exact frozen host. Do not substitute an independently re-signed shipping clone or edit package fingerprints to make earlier packages appear current. Use `--source-mode interim` for partial or historical measurements; missing provenance remains explicitly unrecorded.

Each downloaded package carries its owning engine role and an ExtensionKit UI carrier. The carrier application and its nested UI worker contain copies of the same host executable code, with their own bundle identities and signatures. Scoped libraries, feature resources and any contained native roles add further bytes. The final generator checks sealed carrier metadata, executable provenance and unsigned code equality against the frozen host. A synthetic Camera host requires its exact source-bound clone receipt, including the allowed identity/signature changes and unchanged resource inventory. Signature bytes can differ after signing different bundle identities. Development ad-hoc signatures and synthetic identities do not establish that artifacts are distributable. Verify actual code signatures, trusted signing team, catalog authenticity and client admission separately.

Installed bytes mean logical regular-file bytes. Count every packaged copy at its actual path, including repeated host executables, carrier resources and private libraries; do not deduct hypothetical filesystem deduplication. Host-plus-package totals include the host and one installed package version per selected feature. They exclude allocation rounding, retained versions, receipts, caches, user data and extra OS-managed deployment copies. APFS allocation and real retained storage must be measured separately. Installing every feature can cost more than the former bundled app because independent packages duplicate code and resources.

The app comparison ZIP uses deflate level 9 and excludes symlinks, matching the retained baseline method. Package download bytes are the actual release ZIP sizes. These controlled ZIP comparisons are distinct from a shipping DMG, whose compression, container metadata and signing overhead differ. Record a measured DMG separately; do not label ZIP savings as DMG savings.

The local release-asset subtotal counts the 39 package ZIPs and their JSON metadata. Actual publication also needs each detached `.zip.sha256` and the shared signed catalog, with its release pointer. Retained releases, catalog revisions and older asset copies add storage beyond that subtotal. Generating the report uploads nothing and does not prove that matching GitHub assets are available or downloadable. Record publication, authenticated catalog selection, actual downloads and installer update/rollback/removal checks separately.

Use the baseline metadata in `local/baseline/current-main-size.json`. The retained source commit `91d0e13de56aaf297ad4630d2c36ef124da5bf0c` records Release, arm64, ad-hoc signing, Xcode 27.0 (27A266a), SDK 27.0 and the pinned Ghostty source commit. Its metadata does not record link-time optimization, so baseline full LTO is unknown. The current minimal-host build explicitly uses Release, `-Osize` and full LTO. Record its actual toolchain, signing operation and source commit rather than inferring them from the baseline. Neither an ad-hoc Release build nor a size comparison proves production signing.

Measure the exact packaged host, including its CLI launcher and shipping metadata when present in that artifact. Supply its existing build metadata with `sourceCommit`, `sourceTreeDirty`, `configuration`, `optimization`, `linkTimeOptimization`, `architecture`, `signature`, `xcode`, `sdk` and `hostExecutableSHA256`. Optional Ghostty fields apply only when relevant to that build. Metadata must match the actual measured executable; supplied configuration values do not replace inspection of the build command. The minimal-host build enforces the accepted empty-app limit of less than 10,000,000 installed bytes independently of report generation. Verify signatures, dependency boundaries, all 39 indexed features and zero bundled feature payloads through the build, shipping and final report checks.

Artifact bytes are not memory measurements. Disabling must drain the owning engine worker, admitted native tasks, commands and registered descendant process groups, and release active presentation resources. Verify this through actual lifecycle results rather than deriving it from package sizes. Native tasks require the worker's live capability, the same signed host executable, kernel peer identity and owned process groups with live birth identities. Arbitrarily detached, unregistered feature processes are outside this contract. OS caches or a separately owned provider can remain resident after the Edith worker exits. Report measured memory, process counts and retirement outcomes separately; do not claim zero memory use from disable or removal alone.

Headless worker checks exercise exact fresh synthetic fixture environments, selected-version admission, update, app replacement, recovery, disable and removal. They report `nativeWindow: false` and do not establish that a managed original view rendered successfully. Nineteen owners use strict issued inert markers; the other twenty require their documented closed fixture paths, defaults and backend restrictions. Background-only verification must not order or activate windows, request permissions, capture hardware or audio, contact live providers, or use real preferences or data. Native managed-view tests require the actual downloaded role, current host registration and an owning presentation; record their approval, view readiness and drain results independently. A skipped UI step or an unacknowledged navigation request is not UI success.

Camera uses the existing [OBS Virtual Camera](https://obsproject.com/kb/virtual-camera-troubleshooting) workaround. Install its provider through OBS once, then keep OBS closed while Edith supplies frames. Disabling Edith stops its capture and frame delivery; Edith does not deactivate or remove the separately owned OBS provider. The package's microphone-only carrier uses a copy of the same Edith executable, without a camera system extension or special provisioning profiles. OS-managed audio drivers require separate retirement proof. Approval or restart-required results are not successful retirement. Removing a meeting-microphone HAL driver from disk can leave loaded code owned by macOS until restart; retain recoverable ownership and report that requirement until retirement completes. Synthetic lifecycle checks must not activate real system extensions, load real audio drivers or manipulate production services.

Run broad desktop checks only on an approved disposable or hosted desktop:

```sh
make ci-marketplace-host
```

This target includes host UI tests and must not be run on a working local desktop under a background-only restriction. Build-only, pure unit and explicitly reviewed headless fixture scopes are separate. After validating the closed fixture prerequisites above, the worker runner retains measured packages without claiming native-window coverage:

```sh
make ci-extension-workers EXTENSION=--retain-packages
```

Report generation itself does not launch the application or workers. After all final artifacts and independent checks exist, set `FINAL_SOURCE_COMMIT`, `FINAL_HOST_APP`, `FINAL_HOST_BUILD_METADATA` and `FINAL_PACKAGE_DIRECTORY` to the exact frozen source and runner artifacts, then generate from the matching clean checkout:

```sh
python3 -B scripts/extension-host-size-report.py --source-mode final --expected-source-commit "$FINAL_SOURCE_COMMIT" --packages "$FINAL_PACKAGE_DIRECTORY" --baseline local/baseline/current-main-size.json --app "$FINAL_HOST_APP" --host-build "$FINAL_HOST_BUILD_METADATA" --output docs/extension-host-rebuild-size-report.json --markdown-output docs/extension-host-rebuild-size-report.md
```

Review all 39 package fingerprints and measured copies against the final host index. Retain lifecycle, native view, memory, signing, platform-retirement and publication evidence separately. Leave the generated final size files unchanged until this complete artifact set exists.
